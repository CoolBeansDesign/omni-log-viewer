xTool Omni Log Viewer

by CoolBeans Design
Print-job, ink and maintenance report for the xTool Omni O1 UV printer (Dual-UV and UV/DT).
🔒
Your logs never leave this computer. Everything is read and analysed inside this browser tab; nothing is uploaded to any server. The logs contain your printer's serial number, network address and computer user name, so keep them private.
Drop xTool log files or folders here
xTool Studio log exports (.gz), zips of xTool Studio's logs folder (.zip), or the logs folder itself. Add as many as you like; overlapping exports are merged.

What to load

  1. The printer's logs. Export them from xTool Studio while the Omni is connected (the device log export). You get one file named like xTool_dt002_log.gz. It holds the printer's own journal (prints, cleans, ink levels) plus the last few days of xTool Studio's logs.
  2. xTool Studio's logs folder from each computer you print from, for job names, layer stacks and per-layer inks going further back. Use Choose a folder… and pick the whole logs folder, or zip the whole folder and drop the zip. Keep its algo-server sub-folders: they hold Studio's slicer log, the only place that says which layers are varnish rather than white.
    Mac
    ~/Library/Application Support/xTool Studio/logs (in Finder: Go → Go to Folder…)
    Windows
    %APPDATA%\xTool Studio\logs (paste into the Explorer address bar)
  3. Older exports are worth keeping: the printer only keeps recent history, and loading several exports together recovers everything that has since rotated out.

Works offline once this page has loaded; it fetches its chart and unzip libraries from public CDNs.

When cartridges reach 20%

How this is worked out
  • Active days: calendar days (your local time) with at least one print job. The forecast uses the 3 most recent ones, or fewer if the logs don't have 3 yet.
  • Use per active day: all the ink the printer recorded from each cartridge on those days, divided by the number of days. The one-time setup priming and setup test prints are left out.
  • Maintenance is included on purpose. When a cartridge reaches 20% the printer forces itself into hibernation, so what matters is everything that drains the cartridge: head cleans, deep cleans, switching a head between ink and moisturizing fluid, and scheduled cleans, as well as printing. On some printers maintenance uses far more ink than printing does, which is why these figures can be much higher than the Ink per print job chart, which shows printing only.
  • Cleans count against every cartridge on that head, so a cartridge you haven't printed with (for example the fluorescent inks) still shows some use.
  • Days without printing are skipped, so they don't dilute the average. Cleans on those days aren't counted either, though in these logs ink use on idle days has been close to zero.
  • Target: 20% of the cartridge's full capacity, starting from the latest level the printer logged.
  • Printing days to 20% = (remaining − 20% of full) ÷ use per active day. The date assumes you print every day from the last reading, so it's the earliest likely date. Printing less often pushes it later.
  • Ink levels are the printer's own calculation (drops fired plus fixed amounts for cleans), not a physical measurement. With only a few active days the forecast is rough and will settle as more logs are added.

Setup ink priming

The first fill at setup fills each ink line before anything prints. The line capacity is the amount the printer logged for filling that line; the rest of each cartridge's setup drop is the printer's fixed allowance for the purge cycles. Both are the printer's own figures, so ink drawn off by syringe during setup isn't counted.

The Rigid White line is a circulation loop, which is why it's so much larger than the others: about 16.6 ml in the supply line, 20 ml in the filter and 10 ml in the return line.

Maintenance summary

Power & sleep

Head idle timers Preliminary · to be confirmed

Each print head's Idle timer counts the time the printer isn't working, including sleep, since that head's last standard clean. A 7-day (604,800 s) limit is assumed to trigger moisturizing; that limit doesn't appear in the logs. The estimate assumes the printer stays idle the same share of the time as in the last 48 hours of the logs.

How the estimate is worked out
  • The 7-day limit is an assumption. No log or setting shows 604,800 s; the card uses it because a 7-day moisturizing cycle is expected for the Omni. If a moisturizing event shows up in a later export, compare its time with this estimate.
  • Rate: how much the Idle timer grew during the last 48 hours of logs, divided by 48 hours (e.g. 93% means the printer was idle 93% of that time). The time left to reach 7 days is divided by that share. More printing than in those 48 hours pushes the date later; less brings it closer.
  • Snapshots: the printer only logs the timer when it changes state (a print starting, going to sleep, waking). The estimate starts from the last logged value, so it stays valid after the export even though the timer has kept counting.
  • Resets aren't predicted. The date assumes that head gets no standard clean before then. A standard clean resets the timer to zero (see below), and the estimate starts over from the next export.
  • Asleep counts as idle. Sleep and low power add to the timer; printing, calibration, height measuring and cleaning don't.

How things are derived

    
    
      
  • Events come from the printer's journal mnt/config/record/record.log: prints, cleans, white-ink stir/circulation, sleep / low-power, boots, calibration, alarms.
    • 
      
  • Ink levels come from ink_tank_status reports in the printer's app-controller logs, written after every clean and print. Usage between two snapshots is assigned to a standalone clean in that window if there is one, otherwise to the job running, otherwise to the latest maintenance event.
    • 
      
  • Job names, passes, time estimates come from task-history replies in the xTool Studio logs.
    • 
      
  • Layer stacks, size, thickness, DPI and planned ink come from the xTool Studio slicer and print parameters logged just before each job was sent. Jobs sent from a different computer (or before these desktop logs start) have no layer detail.
    • 
      
  • Per-layer inks (white, flexible white, varnish or colour) come from [GenPd] lines in xTool Studio's slicer log logs/<date>/algo-server/server.log, matched to jobs by task ID. That file lives under the day Studio was started and keeps growing on later days. Without it the layer stack falls back to the slicer settings, which call varnish layers "white"; those jobs are marked ⚠.
    • 
      
  • Tank names are the ones the printer reports for each cartridge. Head 1 holds UV Cyan, Magenta, Yellow, Black, Varnish and White. On a Dual-UV, head 2 holds Fluorescent Yellow, Fluorescent Red, Flexible White and Rigid White; on a UV/DT it holds DTG Cyan, Magenta, Yellow, Black and White. The model is worked out from the cartridges on head 2. Studio's ink channels map as C→Cyan, M→Magenta, Y→Yellow, K→Black, V→Varnish, W→White, HW→Rigid White and SW→Flexible White, and DTG_C/M/Y/K/W→the DTG cartridges (HW checked against measured drops).
    • 
      
  • Clock: printer timestamps are converted using the detected offset shown above, and everything is shown in this browser's local time.
